# Jesters

An asynchronous multiplayer trick-taking card game for iOS, played by the rules of Wizard.
See [PLAN.md](PLAN.md) for the rules, architecture and milestones.

```
backend/            Firebase project: Cloud Functions (Node.js/TypeScript), Firestore rules, emulator config
  functions/        Cloud Functions source, tests
ios/                SwiftUI app (Xcode project generated by XcodeGen from project.yml)
.github/workflows/  CI for the backend and the iOS app
```

## Local development

Everything runs against the **Firebase Emulator Suite** with the `demo-jesters` project,
so no real Firebase project or credentials are needed.

### Backend

Requirements: Node.js 22, [pnpm](https://pnpm.io) (`corepack enable` installs the version from `package.json`) and Java 21+ (for the Firestore emulator).

```sh
cd backend/functions
pnpm install
pnpm lint && pnpm typecheck
pnpm test                # unit tests
pnpm test:emulator       # integration tests against the emulators
pnpm emulators           # start the emulators (UI at http://127.0.0.1:4000)
```

### iOS

Requirements: Xcode 16 or later and [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).

```sh
cd ios
xcodegen generate        # creates Jesters.xcodeproj (not committed; run it again after changing project.yml or adding files)
open Jesters.xcodeproj
```

Start the emulators (`pnpm emulators` in `backend/functions`) and run the app in the simulator.
Each simulator signs in as its own guest, so to play a game, run the app on three simulators
(e.g. iPhone 16, iPhone 16 Plus and iPhone SE): create a game on one and join with its room key
on the others. The emulator UI at http://127.0.0.1:4000 shows the Firestore documents live.

Without a `GoogleService-Info.plist`, the app always uses the local emulators. With one, the
Debug scheme still uses the emulators because of the launch argument `-useFirebaseEmulator YES`.
Untick that argument in the scheme to use the real project.

## Firebase project setup (needed only for deploying)

All regional resources live in **`europe-west3` (Frankfurt)**; see PLAN.md §2 for the data location.

1. Create two Firebase projects (e.g. `jesters-dev` and `jesters-prod`) and put their IDs into
   `backend/.firebaserc`. **Turn off Google Analytics** when creating them.
2. In each project:
   - upgrade to the **Blaze** plan (required for Cloud Functions),
   - whenever the console asks for a location (default resource location, Firestore, Cloud Scheduler), choose `europe-west3`,
   - accept Google's data processing terms (GDPR) in the project's privacy settings,
   - enable **Authentication → Anonymous**,
   - create **Firestore** in `europe-west3` (Frankfurt), the same region as the functions,
   - add an **iOS app** with bundle ID `design.lucidity.jesters`, download `GoogleService-Info.plist`
     and put it in `ios/Jesters/Resources/` (it is git-ignored).
3. Deploy manually: `cd backend/functions && pnpm exec firebase login && pnpm run deploy:dev`.

### App Check

The callables only accept requests from the genuine app (`ENFORCE_APP_CHECK` in
`backend/functions/.env`; the emulators run without it). In each Firebase project:

1. **App Check → Apps:** register the iOS app with **App Attest**.
2. Debug builds and the simulator use the debug provider: on launch the app logs
   `Firebase App Check debug token: …`. Add it under **App Check → Apps → Manage debug tokens**.
3. After a test round, also turn on enforcement for **Firestore** and **Authentication** in the
   App Check console (the callables already enforce it).

The app uses no App Check while it talks to the emulators.

### Push notifications

1. In the Apple Developer account, create an **APNs authentication key** (.p8) and upload it in
   the Firebase console under **Project settings → Cloud Messaging → Apple app configuration**
   (for each Firebase project).
2. In Xcode, select your development team for the `Jesters` target. The push entitlement is
   already set in `project.yml`.
3. Notifications need the real Firebase project (not the emulators) and a device, or a simulator
   on an Apple-silicon Mac.

The app asks for permission after the player creates or joins a game. Notification texts are
translated on the device (`PUSH_*` keys in `Localizable.xcstrings`).

### Invite links

The app opens `jesters://join/<room key>` and pre-fills the join screen. It also understands
`https://<domain>/join/<room key>`, which will work as soon as a domain with Universal Links is set up.

### Privacy

- `docs/privacy-policy.md` is a draft in German and English. Fill in the controller's details,
  have it reviewed and publish it on a website. Set its address as `PrivacyPolicyURL` in
  `ios/project.yml` (and as the `PRIVACY_POLICY_URL` variable for TestFlight builds); the profile
  screen shows the link once it is set.
- Players delete their data in the app under **Profile → Delete my data** (`deleteMyData`).
- `ios/Jesters/Resources/PrivacyInfo.xcprivacy` declares the collected data for the App Store.
  Answer App Store Connect's privacy questions the same way: user ID, name, device ID (push token),
  gameplay content and other data (time zone, language), all linked to the user, for app
  functionality, no tracking.

### Deploying from CI

The `Backend` workflow deploys `main` to the dev project and `v*` tags to the prod project.
Deploying is off until it is configured:

1. Set up [Workload Identity Federation](https://github.com/google-github-actions/auth#workload-identity-federation-through-a-service-account)
   for this repository, with a service account that can deploy to Firebase.
2. Create the GitHub environments `dev` and `prod`. In each, set the variables
   `GCP_WORKLOAD_IDENTITY_PROVIDER` and `GCP_SERVICE_ACCOUNT`.
3. Set the repository variable `DEPLOY_ENABLED` to `true`.

### TestFlight

The `TestFlight` workflow archives the app against the prod Firebase project and uploads it to
App Store Connect, for every `v*` tag (`v1.2.0` → version 1.2.0) or by hand. It is off until it is
configured:

1. Create the app in App Store Connect with bundle ID `design.lucidity.jesters`.
2. Create an **App Store Connect API key** with the *Admin* role (needed for cloud signing).
3. In the GitHub environment `prod`, set
   - the variables `APPLE_TEAM_ID`, `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`
     and `PRIVACY_POLICY_URL`,
   - the secrets `APP_STORE_CONNECT_KEY` (the contents of the `.p8` file) and
     `GOOGLE_SERVICE_INFO_PLIST` (the prod `GoogleService-Info.plist`, base64-encoded:
     `base64 -i GoogleService-Info.plist | pbcopy`).
4. Set the repository variable `TESTFLIGHT_ENABLED` to `true`.
